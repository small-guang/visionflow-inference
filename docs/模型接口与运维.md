## 1. 契约范围

### 1.1 统一在线批量契约

运行时只维护一套批量配置：全链路 `max_batch_size: 4`，客户端必须显式传入 batch 首维并遵守 `1 <= B <= 4`。14 个推理节点最多等待 2 ms 组批；上线前仍必须执行逐样本 parity、数值、显存、吞吐和延迟测试。

下表是 14 个公开入口的完整运行时 shape；配置中的 `dims` 仍只描述单样本，Triton
在最前面管理 `B`。OSNet 编码图片中的 `L` 是尾部补零后的共同长度；SBS、TBPS image 和 CLIP image 使用 BYTES `[B,1]`，每个元素保留完整编码字节。

| 对外模型 | 批量输入 | 批量输出 |
| --- | --- | --- |
| `yolov8n_face_ensemble` | `RAW_IMAGE [B,H,W,3]` | `DETECTIONS [B,100,6]`, `NUM_DETECTIONS [B,1]` |
| `face_keypoint_2d106_ensemble` | `RAW_IMAGE [B,H,W,3]`, `BBOX [B,4]` | `LANDMARKS_106 [B,106,2]` |
| `face_qa_ensemble` | `RAW_FACE_IMAGE [B,H,W,3]`, `LANDMARK [B,5,2]` | `quality_score [B,1]` |
| `sixdrepnet_ensemble` | `RAW_FACE_IMAGE [B,H,W,3]` | `HEAD_POSE [B,3]` |
| `face_recognition_pipeline` | `RAW_IMAGE [B,H,W,3]`, `LANDMARK [B,5,2]` | `EMBEDDING [B,512]` |
| `adaface_recognition_pipeline` | `RAW_IMAGE [B,H,W,3]`, `LANDMARK [B,5,2]` | `EMBEDDING [B,512]` |
| `sbs_r50_ibn_image_ensemble` | `IMAGE_BYTES [B,1]` | `embedding [B,2048]` |
| `osnet_ain_x1_0_image_ensemble` | `IMAGE_BYTES [B,L]` | `embedding [B,512]` |
| `clip_ensemble_trt` | `IMAGE_BYTES [B,1]` | `unnorm_image_features [B,512]` |
| `clip_text_ensemble` | `TEXT [B,1]` | `unnorm_text_features [B,512]` |
| `TBPS_clip_image_ensemble` | `IMAGE_BYTES [B,1]` | `image_feat [B,512]` |
| `TBPS_clip_text_ensemble` | `TEXT_IN [B,1]` | `text_feat [B,512]` |
| `yolo26m_pose_ensemble` | `RAW_IMAGE [B,H,W,3]` | `DETECTIONS [B,100,6]`, `KEYPOINTS [B,100,17,3]`, `NUM_DETECTIONS [B,1]` |
| `yolo26s_seg_ensemble` | `RAW_IMAGE [B,H,W,3]` | `DETECTIONS [B,M,6]`, `MASK_CROPS_PACKED [B,M,160,20]`, `NUM_DETECTIONS [B,1]` |

`person_seg` 的检测维 `M` 是一次响应内所有样本共享的动态容量：`M = max(1, max(NUM_DETECTIONS))`，并且 `1≤M≤100`。`100` 是每张图片的检测上限，不是固定输出维度。`DETECTIONS[b,i]` 与 `MASK_CROPS_PACKED[b,i]` 一一对应；`i >= NUM_DETECTIONS[b,0]` 的槽位为零填充。原始图片同一请求内仍必须具有相同 `H`、`W`；不同尺寸图片需要拆分请求，或由调用方按相同 wire shape 分组后再批处理。

### 1.2 ALog 公开契约版本

供 ALog 调用的 10 个公开入口必须在各自 public `ModelConfig.parameters` 中声明 `api_contract_version`。该值必须是只包含十进制数字的字符串（numeric string）。`yolo26s_seg_ensemble` 当前为 `"3"`；`face_qa_ensemble`、`yolov8n_face_ensemble`、`yolo26m_pose_ensemble`、`sbs_r50_ibn_image_ensemble` 和 `TBPS_clip_image_ensemble` 为 `"2"`；其余 4 个入口为 `"1"`；ALog 通过远程 gRPC `get_model_config` 读取 `max_batch_size` 和 `api_contract_version`，通过 `get_model_metadata` 读取 tensor schema，并校验对应 adapter 的契约。ALog 与 Triton 不需要共享模型目录或本地配置文件。

当前这 10 个入口是：`clip_ensemble_trt`、`face_recognition_pipeline`、`TBPS_clip_image_ensemble`、`sbs_r50_ibn_image_ensemble`、`face_qa_ensemble`、`face_keypoint_2d106_ensemble`、`yolov8n_face_ensemble`、`yolo26s_seg_ensemble`、`yolo26m_pose_ensemble` 和 `sixdrepnet_ensemble`。其余 4 个公开入口不属于当前 ALog adapter 集合，不应仅为文档统一而补写该参数。

只改变 `max_batch_size` 不改变 `api_contract_version`。下列任一公开契约发生变化时，必须递增版本，并在同一变更中同步更新 ALog adapter：tensor 名、dtype 或 rank；颜色或归一化；坐标约定；padding 策略；embedding space；输出语义。

## 2. 部署后端与公开入口

### 2.1 后端状态

- 3 个节点继续使用 ONNX Runtime：`adaface_ir50_webface4m_onnx`、`osnet_ain_x1_0_onnx`、`sixdrepnet_onnx`，由各自的 `1/model.onnx` 提供活动模型。
- 11 个节点使用 `backend: "tensorrt"`：`clip_image_trt`、`clip_text_trt`、`TBPS_clip_image_trt`、`TBPS_clip_text_trt`、`sbs_r50_ibn_onnx`、`w600k_r50_trt`、`face_qa`、`face_keypoint_2d106`、`yolov8n_face_onnx`、`yolo26m_pose_onnx`、`yolo26s_seg_onnx`。内部名称保留以兼容 API 与 ensemble 映射；活动运行时只加载 `1/model_throughput.plan`。原有 `1/model.onnx` 作为离线构建与数值参考源保留，不由这 11 个运行节点加载；全部 14 份 ONNX 及其哈希记录继续维护。
- `TRITON_MODEL_SET=all` 时启动器不注入模型控制参数，Triton 按默认模型控制和 strict readiness 扫描整个仓库；subset 时启动器注入 `--model-control-mode=explicit` 与所选闭包的 `--load-model` 参数。

### 2.2 对外入口摘要

完整请求/响应 shape 以 1.1 节的 14 项统一契约为准。调用方不得省略 batch 首维，并遵守 `1 <= B <= 4`；颜色、归一化和模型用途见第 4、6 节，内部调度见第 8 节。

## 4. 颜色通道与图像数据契约

### 4.1 总规则

- `RAW_IMAGE`、`RAW_FACE_IMAGE`：服务边界统一接收 OpenCV 风格 **BGR、HWC、UINT8、0–255**。
- `IMAGE_BYTES`：传输的是完整 JPEG/PNG 等编码字节，本身没有 RGB/BGR。只有解码成像素后才谈颜色顺序。
- 不要在调用 `RAW_IMAGE` 前自行执行 BGR→RGB；各预处理节点已经按底层模型要求转换一次。
- 颜色、resize、归一化、对齐或权重任一变化，都可能改变检测、关键点、质量分和 embedding。

### 4.2 当前颜色链路矩阵

| Pipeline | 服务边界到推理模型的实际链路 |
| --- | --- |
| `yolov8n_face_ensemble` | BGR HWC → letterbox（仍为 BGR）→ `image[:, :, ::-1]` 得 RGB → `/255` → FP32 NCHW `[1,3,H',W']` |
| `yolo26m_pose_ensemble` | BGR HWC → letterbox → BGR→RGB → `/255` → FP32 NCHW `[1,3,H',W']` |
| `yolo26s_seg_ensemble` | BGR HWC → letterbox → BGR→RGB → `/255` → FP32 NCHW `[1,3,H',W']` |
| `face_keypoint_2d106_ensemble` | BGR HWC → bbox 仿射到 `192×192` → `blobFromImage(swapRB=True)` 一次转 RGB → FP32 `[1,3,192,192]`，像素仍为 0–255；图内完成 Sub/Mul |
| `face_qa_ensemble` | BGR HWC + 图内 ArcFace 顺序五点 → 相似变换对齐到 `112×112` → 一次 `COLOR_BGR2RGB` → `(x/255-0.5)/0.5` → FP32 CHW `[3,112,112]` |
| `sixdrepnet_ensemble` | BGR HWC → RGB → 短边等比缩放到 224 → 中心裁剪 `224×224` → ImageNet mean/std → FP32 CHW `[3,224,224]` |
| `face_recognition_pipeline` | BGR HWC → ArcFace 五点仿射到 `112×112` → `blobFromImages(swapRB=True)` 一次转 RGB → `(x-127.5)/127.5` → FP32 CHW `[3,112,112]` |
| `adaface_recognition_pipeline` | BGR HWC → AdaFace 五点相似变换对齐到 `112×112` → **保持 BGR，不交换通道** → `(x-127.5)/127.5` → FP32 CHW `[3,112,112]` |
| `sbs_r50_ibn_image_ensemble` | 编码字节 → OpenCV 解码 BGR → 一次 `COLOR_BGR2RGB` → `384×128` → ImageNet mean/std → FP32 CHW |
| `osnet_ain_x1_0_image_ensemble` | 编码字节 → Pillow `convert("RGB")` → `256×128` → ImageNet mean/std → FP32 CHW |
| `clip_ensemble_trt` | BYTES → OpenCV 解码 BGR → 一次 `COLOR_BGR2RGB` → OpenCV cubic 直接拉伸 resize 到 `224×224`（无 crop）→ Chinese-CLIP mean/std → FP32 `[1,3,224,224]` |
| `TBPS_clip_image_ensemble` | 编码 BYTES → Pillow RGB → Pillow bicubic 直接拉伸 resize 到 `224×224`（无 crop）→ ImageNet mean/std → FP32 `[1,3,224,224]` |
| 两个文本 CLIP | UTF-8 文本 → tokenizer → INT64 token IDs；无颜色概念 |

ImageNet 统计量：`mean=[0.485,0.456,0.406]`，`std=[0.229,0.224,0.225]`。Chinese-CLIP 图像统计量：`mean=[0.48145466,0.4578275,0.40821073]`，`std=[0.26862954,0.26130258,0.27577711]`。

### 4.3 数据版本兼容

持久化向量、关键点和质量分时，应关联模型权重、预处理及输出契约版本。不同颜色、归一化或对齐规则生成的数据不能直接混用；变更影响与重新计算范围见[模型更新与数据迁移](#9-模型更新与历史数据迁移)。

## 5. Batch 与 shape 规则

### 5.1 Triton 隐式 batch

- `config.pbtxt` 的 `dims` 不含最前面的 batch，客户端始终必须显式添加 `B`，并遵守 `1 <= B <= 4`（即 `B<=4`）。
- 同一个 dense 请求中的所有样本必须共享全部非 batch 维度。例如 `RAW_IMAGE [B,H,W,3]` 的每一行必须有相同 `H`、`W`、通道数和 dtype，不能用 ragged tensor 混装不同尺寸。
- 多输入入口的相关 tensor 必须共享同一个 `B`。例如 `RAW_IMAGE [B,H,W,3]` 与 `LANDMARK [B,5,2]`，或 `RAW_IMAGE [B,H,W,3]` 与 `BBOX [B,4]`，必须逐行对应。
- ONNX Runtime、TensorRT 和 Python 内部同样保留 batch 首维，Ensemble 只传递该逻辑 batch，不自行 `squeeze`、`unsqueeze` 或固定取第 0 行；TensorRT engine 的 batch 范围由构建 profile 固定。

### 5.2 单一运行配置与动态调度

根配置中的 14 个 Ensemble 使用 `max_batch_size: 4` 与原有 `ensemble_scheduling`；34 个 ONNX Runtime/TensorRT/Python 可执行节点均使用 `max_batch_size: 4`，其中 `clip_image_preprocess` 为 `count: 2`，其余 33 个节点为 `count: 1`。选择 `TRITON_MODEL_CONFIG=orin_gpu` 时，`yolov8n_face_ensemble` 与 `yolo26s_seg_ensemble` 改用各自 `configs/orin_gpu.pbtxt` 中的 Python GPU 后端，分别为 `count: 4`、`count: 2`；`yolo26m_pose_ensemble` 与 `TBPS_clip_image_ensemble` 的具名配置仍为 `count: 1`。实例数修改需重新加载模型或重启 Triton 才会生效。根配置中 14 个推理节点（11 个 TensorRT、3 个 ONNX Runtime）增加最多 2 ms 的组批等待：

```protobuf
dynamic_batching {
  max_queue_delay_microseconds: 2000
}
```

20 个 Python 前后处理节点仍使用空 `dynamic_batching {}`，不额外等待，避免在链路多个阶段重复引入组批等待。兼容请求可在每个可执行节点合并到总 batch 4；“兼容”要求输入名称、dtype、rank 与全部非 batch 维度一致。配置文件不显式设置 `preferred_batch_size`，任何节点都没有 `allow_ragged_batch`。

2 ms 是调度器为了凑批允许的额外等待，不是总排队时间或端到端延迟上限；凑满 batch 4 且实例可用时无需等满 2 ms，等待到期也会发送未满的 batch。它不能消除 shape 不兼容或客户端串行提交造成的组批限制，上线后仍需对比平均执行 batch 和端到端延迟。

这些调度规则直接维护在各模型的根 `config.pbtxt`，没有配置生成步骤。修改文件不会更新已加载模型的调度器；需要在维护窗口重新加载模型或重启 `triton-server`。从旧的具名备选配置版本升级时，还必须用 `docker compose up -d --build` 重建包含新启动器的 launcher 镜像；原有 `TRITON_MODEL_SET` alias 选择保持不变。

### 5.3 编码图片的 BYTES/UINT8 兼容规则

- `TYPE_STRING`/客户端 `BYTES` 的公开输入使用 `[B,1]`。每个元素可保存不同长度的完整编码图片或 UTF-8 文本；元素的字节长度不是 dense tensor 维度，所以只要 wire shape 仍为 `[B,1]`，长度不同本身不会造成 shape 不兼容。
- `TYPE_UINT8`/客户端 `UINT8` 的编码图片输入使用 dense `[B,L]`。`L` 是真实的非 batch 维度：同一请求中每行必须有相同 `L`，不同请求只有 `L` 相同时才能被动态合并。只有 OSNet 继续使用这个输入契约，短编码可在右侧补零到共同 `L`；解码器依赖编码格式容忍尾部数据。OSNet 调用方应按 `L` 建 bucket，而不是把不同长度做成 ragged tensor。
- SBS 和 TBPS image 的 API v2 使用 `np.array([[encoded_bytes], ...], dtype=object)`，不再补零或按编码长度分桶。每个元素必须是非空 `bytes`，嵌入及尾部的零字节原样送入现有 OpenCV/Pillow 解码器；拒绝字符串、数值、空元素以及非 `[B,1]` 的输入。不要使用会截断尾部 NUL 的 NumPy 固定宽度字符串 dtype。
- 两种表示不可互换：`BYTES [B,1]` 的元素是 `bytes` 对象，`UINT8 [B,L]` 是数值数组。不要把原始 BGR 像素矩阵放进编码 `IMAGE_BYTES`，也不要把 UINT8 数组作为 BYTES object 发送。

### 5.4 YOLO 固定矩形尺寸分桶

三个 YOLO 公开入口接收 `RAW_IMAGE [B,H,W,3]`。预处理先用 `r = min(640/H, 640/W)` 保持比例缩放，宽高分别四舍五入；再从 `(192, 384, 480, 640)` 中分别选择不小于缩放后高、宽的最小值作为补边目标。缩放后最长边总是 640，因此模型实际输入只有以下 7 档（均为 **高×宽**）：

| 图片形状 | 横向输入 | 竖向输入 |
| --- | --- | --- |
| 超宽或细长 | `192×640` | `640×192` |
| 常用横图或竖图 | `384×640` | `640×384` |
| 较接近方形的横图或竖图 | `480×640` | `640×480` |
| 方形档 | `640×640` | `640×640` |

选择依据是缩放并取整后的尺寸能否完整放入该档位。图像居中补 BGR `(114,114,114)`；奇数补边的额外一像素放在右侧或下侧。内容缩放比例保持不变，不为进入更小档位而继续缩小图像。例如原图 `1080×1920` 得到 `384×640`；`101×200` 得到 `384×640`（上 30、下 31）；`120×80` 得到 `640×480`（左 26、右 27）。三个前处理及后处理中的 `LETTERBOX_BUCKET_SIZES` 必须同步修改。

每个 YOLO 保留一份动态 ONNX 源，内部 `images` 的 `dims: [3,-1,-1]` 用于承载这些不同档位；每个模型离线构建一个原生 TensorRT engine，用一个动态 optimization profile 覆盖七档尺寸和 `1<=B<=4`，无需按档位分别导出 ONNX 或 engine。固定档位减少 shape 种类，但性能收益应在目标设备上实测。

调用方先按原始 `(H,W)` 建立 `shape bucket`：不同 H/W 图片必须作为独立请求发送，不能组成 ragged 请求。预处理后的固定 `(H',W')` 是下一层 shape bucket key；只有档位相同的结果才能在 YOLO TensorRT 节点动态合并。固定内部尺寸不会自动合并客户端的不同原图 bucket。

人脸检测与姿态入口的 `api_contract_version` 为 `2`，分割入口为 `3`。坐标还原与 mask 裁剪使用相同的缩放和补边几何，非规范补边元数据会被拒绝。上线前用横图、竖图、全景图和无目标图检查召回、关键点及 mask 对齐。

#### 5.4.1 原生 TensorRT plan

2.1 节的 11 个原生节点直接加载离线 plan，不配置 ORT 的 `optimization.execution_accelerators` 块。内部名称、公开入口、ensemble 映射、预处理、后处理及 `api_contract_version` 保持不变。图像输入和全部模型输出保持 FP32；`clip_text_trt` 的 `text [B,52]` 与 `TBPS_clip_text_trt` 的 `text [B,77]` 始终为 INT64，不因内部构建精度而改为 INT32/FP16。

以下文件、实例和调度规则适用于全部 11 个节点；表中的 `images` shape 范围仅用于三个 YOLO，七档尺寸沿用 5.4 节。

| 参数 | 活动部署 |
| --- | --- |
| Triton `max_batch_size` | `4` |
| `default_model_filename` | `model_throughput.plan` |
| GPU instance / engine profile | `count: 1` / `profile: ["0"]` |
| `trtexec --minShapes` | `images:1x3x192x192` |
| `trtexec --optShapes` | `images:1x3x384x640` |
| `trtexec --maxShapes` | `images:4x3x640x640` |
| 构建 workspace | `1024 MiB` |
| 动态组批等待 | `max_queue_delay_microseconds: 2000` |

这些 YOLO shape 是包含 batch 的 NCHW。`192×192` 只定义 H/W 各自的下界，公开链路仍只产生七档尺寸；`opt` 以 batch 1 的常用横图为优化点。该范围不是七档输入的白名单，直接调用内部 TensorRT 节点仍需遵守模型自身的维度要求。活动文件内部只有 optimization profile `0`。调整档位或 batch 时，必须同步修改构建范围和根配置，并重建受影响的 plan；没有配置生成步骤。保留的 ORT accelerator 兼容逻辑不表示这些节点仍使用 ORT。

八个固定输入节点仅 batch 维动态，空间尺寸和 token 长度固定；min/opt 均为 B1，max 为 B4：

| 内部模型 | 输入 dtype | min = opt | max |
| --- | --- | --- | --- |
| `clip_image_trt` | FP32 | `image:1x3x224x224` | `image:4x3x224x224` |
| `clip_text_trt` | INT64 | `text:1x52` | `text:4x52` |
| `TBPS_clip_image_trt` | FP32 | `image:1x3x224x224` | `image:4x3x224x224` |
| `TBPS_clip_text_trt` | INT64 | `text:1x77` | `text:4x77` |
| `sbs_r50_ibn_onnx` | FP32 | `image:1x3x384x128` | `image:4x3x384x128` |
| `w600k_r50_trt` | FP32 | `input.1:1x3x112x112` | `input.1:4x3x112x112` |
| `face_qa` | FP32 | `input:1x3x112x112` | `input:4x3x112x112` |
| `face_keypoint_2d106` | FP32 | `data:1x3x192x192` | `data:4x3x192x192` |

使用 `python -m tools.model_pipeline plan` 从完整 ONNX 构建独立候选，`--max-batch` 必须显式给出；B1/B4/B8 参数及主机/容器命令见[模型下载与转换](模型下载与转换.md#3-onnx-转为-plan)。该入口显式选择模型和输出目录，不读取 `.env`。底层 `tools/build_tensorrt_plans.py` 与 YOLO 兼容 CLI 固定生成 B1～4 `model_throughput.plan`，不接受运行配置参数；直接调用可能写入模型仓库。

Face QA 和 106 点默认 FP32，其余原生模型默认 FP16；`--precision fp32` 可覆盖精度，并禁用 TF32。构建使用 workspace 1024 MiB 和 `--skipInference`，产物包含 plan、同名 JSON 和日志。构建成功只说明 engine 已生成，还需完成以下验证：

| 模型 | 目标设备验证重点 |
| --- | --- |
| 全部模型 | 对照 ONNX 参考，检查输出 shape、有限 FP32 数值及所选 batch 的逐行一致性 |
| Chinese-CLIP / TBPS | 真实 token、短文本与长度边界、图文配对和检索排序 |
| w600k / SBS | embedding 余弦、归一化约定和同人/异人排序 |
| Face QA | 原始质量输出、最终分数和阈值排序 |
| 106 点 | 关键点坐标及下游对齐 |
| 三个 YOLO | 七档尺寸下的检测、姿态及 mask 对齐 |

容差按业务基线确定。FP16 未满足要求时，在新的候选目录用 `--models <模型名> --precision fp32` 重建并复验。目标 GPU、架构、TensorRT、源 ONNX、精度或 shape 范围变化时，都需重新构建和验证。

B1/B4/B8 候选保持为独立实验；当前只把验证过的 B1～4 engine 部署为 `model_throughput.plan`，保留对应 JSON、日志和源 ONNX。旧 B1 `model.plan` 只作历史制品保留，不加载、不作为回退，也不通过复制、改名或重新构建改写 engine 字节。旁车中的 plan 文件名、成功日志名与路径需和部署位置一致。发布与回滚检查见[第 9.2 节](#92-发布与回滚检查表)。

加载前检查内部 config 的 backend、文件名、batch 和 optimization profile；加载后检查 repository index 和日志，预热各固定形状及 YOLO 七档尺寸，验证 batch 1～4。原生 TensorRT 不会自动从 ONNX 构建缺失的 engine，也没有 ORT/CUDA EP/CPU 自动回退；ORT TensorRT EP 的子图缓存不能改名充当完整 plan。

workspace 是构建预算，不是模型或进程的总显存上限。性能验证分别测量构建峰值、预热后稳定显存/系统内存、吞吐及端到端 P50/P95；Jetson 还需观察共享物理内存和 swap。

回滚应成组恢复前一个已验证的批量发布，包括匹配的模型制品、根配置、启动器镜像和 alias 闭包 manifest；不把历史 B1 plan 当作活动回退。如果切换后端，还须恢复对应后端的配置并重新加载完整链路。

### 6.1 `yolov8n_face_ensemble`

链路：`RAW_IMAGE` → `yolov8n_face_preprocess` → `yolov8n_face_onnx` → `yolov8n_face_postprocess`。

| Tensor | 请求/响应 shape | 含义 |
| --- | --- | --- |
| `RAW_IMAGE` UINT8 | `[B,H,W,3]` BGR | OpenCV 原图；示例使用显式 `B=1`，batch 上限见第 5 节 |
| `DETECTIONS` FP32 | `[B,100,6]` | 每个 batch 行的检测结果；每行 `[x1,y1,x2,y2,score,class_id]`，坐标已映射到原图 |
| `NUM_DETECTIONS` INT32 | `[B,1]` | 每个样本的有效行数；只读取所选 batch 行的前 `count` 行 |

后处理阈值：置信度 `0.5`、IoU NMS `0.45`、最多 100 个框。当前模型在 640×640 输入下输出 `[1,5,8400]`，类别 `0` 表示 face。

#### 完整调用示例：`yolov8n_face_ensemble`

```python
import os
from pathlib import Path

import cv2
import numpy as np
import tritonclient.http as httpclient

url = os.environ.get("TRITON_HTTP_URL", "127.0.0.1:8000")
image_path = Path(os.environ["TRITON_SAMPLE_IMAGE"])
image = cv2.imread(str(image_path), cv2.IMREAD_COLOR)
if image is None:
    raise RuntimeError(f"cannot read image: {image_path}")

client = httpclient.InferenceServerClient(url=url, verbose=False)
image_batch = np.ascontiguousarray(image[None, ...], dtype=np.uint8)
raw_image = httpclient.InferInput("RAW_IMAGE", list(image_batch.shape), "UINT8")
raw_image.set_data_from_numpy(image_batch)
response = client.infer(
    model_name="yolov8n_face_ensemble",
    inputs=[raw_image],
    outputs=[
        httpclient.InferRequestedOutput("DETECTIONS"),
        httpclient.InferRequestedOutput("NUM_DETECTIONS"),
    ],
)
detections_batch = response.as_numpy("DETECTIONS")
counts = response.as_numpy("NUM_DETECTIONS")
if detections_batch.shape[0] != 1 or counts.shape != (1, 1):
    raise RuntimeError("response batch size must be 1")
count = int(counts[0, 0])
valid = detections_batch[0, :count]
print("count:", count)
print("response detections shape:", detections_batch.shape)
print("valid [x1,y1,x2,y2,score,class_id]:\n", valid)
```

### 6.2 `face_keypoint_2d106_ensemble`

链路：BGR 原图和人脸框 → `face_keypoint_2d106_pre` 仿射裁剪/一次 BGR→RGB → `face_keypoint_2d106` → `face_keypoint_2d106_post` 逆仿射回原图。

`BBOX` 必须是原图坐标 `[x1,y1,x2,y2]`，且 `x2>x1`、`y2>y1`。输出点顺序是 InsightFace 2d106 的 106 点定义。

#### 完整调用示例：`face_keypoint_2d106_ensemble`

```python
import os
from pathlib import Path

import cv2
import numpy as np
import tritonclient.http as httpclient

url = os.environ.get("TRITON_HTTP_URL", "127.0.0.1:8000")
image_path = Path(os.environ["TRITON_SAMPLE_IMAGE"])
image = cv2.imread(str(image_path), cv2.IMREAD_COLOR)
if image is None:
    raise RuntimeError(f"cannot read image: {image_path}")

bbox = np.fromstring(
    os.environ["TRITON_FACE_BBOX"], dtype=np.float32, sep=","
)
if bbox.shape != (4,) or bbox[2] <= bbox[0] or bbox[3] <= bbox[1]:
    raise ValueError("TRITON_FACE_BBOX must be x1,y1,x2,y2")

client = httpclient.InferenceServerClient(url=url, verbose=False)
image_batch = np.ascontiguousarray(image[None, ...], dtype=np.uint8)
bbox_batch = np.ascontiguousarray(bbox[None, ...], dtype=np.float32)
raw_image = httpclient.InferInput("RAW_IMAGE", list(image_batch.shape), "UINT8")
raw_image.set_data_from_numpy(image_batch)
```

### 6.3 `face_qa_ensemble`

链路：BGR 人脸图 + 五点 → `face_qa_pre` 相似变换对齐 → `face_qa` → `face_qa_postprocess`。五点顺序与 6.4 节一致：图像左眼、图像右眼、鼻尖、图像左嘴角、图像右嘴角，坐标相对于 `RAW_FACE_IMAGE`。底层模型输出 10 个序数回归值；ModelScope 原 Pipeline 对 10 个值取均值，当前公开接口为保持既有业务标度输出 `10 × mean(quality)`，得到连续 0–10 分，越高表示质量越好。

该入口的 `api_contract_version` 为 `2`。v1 的“逐项与 0.5 比较后计数”整数分与 v2 连续分不能混用；持久化分数必须记录版本并按 v2 重算。

#### 完整调用示例：`face_qa_ensemble`


### 6.4 `face_recognition_pipeline`

链路：BGR 原图和 ArcFace 五点 → `face_rec_pre` 对齐/一次 BGR→RGB → `w600k_r50_trt` → 512 维原始 embedding。Triton 输出没有额外 L2 归一化；使用 cosine/IP 检索前应在调用方归一化，并保持历史库与当前权重、颜色和对齐版本一致。

五点按**图像坐标从左到右**描述为：图像左侧眼中心、图像右侧眼中心、鼻尖、图像左侧嘴角、图像右侧嘴角。由当前 106 点转五点时使用：

- 图像左侧眼中心：106 点索引 33–42 的均值；
- 图像右侧眼中心：索引 87–96 的均值；
- 鼻尖：索引 86；
- 图像左侧嘴角：索引 52；
- 图像右侧嘴角：索引 61。

这组 106→5 映射属于集成客户端契约；Triton 仓库只输出 106 点，本身没有 106→5 节点。后续变更索引或左右顺序前，应先加入固定数组用例，并同步更新调用端和本文。

#### 完整调用示例：`face_recognition_pipeline`

```python
import os
from pathlib import Path

import cv2
import numpy as np
import tritonclient.http as httpclient

url = os.environ.get("TRITON_HTTP_URL", "127.0.0.1:8000")
image_path = Path(os.environ["TRITON_SAMPLE_IMAGE"])
image = cv2.imread(str(image_path), cv2.IMREAD_COLOR)
if image is None:
    raise RuntimeError(f"cannot read image: {image_path}")
bbox = np.fromstring(
    os.environ["TRITON_FACE_BBOX"], dtype=np.float32, sep=","
)
if bbox.shape != (4,):
    raise ValueError("TRITON_FACE_BBOX must be x1,y1,x2,y2")

client = httpclient.InferenceServerClient(url=url, verbose=False)
image_batch = np.ascontiguousarray(image[None, ...], dtype=np.uint8)
bbox_batch = np.ascontiguousarray(bbox[None, ...], dtype=np.float32)
raw_for_kps = httpclient.InferInput("RAW_IMAGE", list(image_batch.shape), "UINT8")
raw_for_kps.set_data_from_numpy(image_batch)
bbox_input = httpclient.InferInput("BBOX", list(bbox_batch.shape), "FP32")
bbox_input.set_data_from_numpy(bbox_batch)
kps_response = client.infer(
    model_name="face_keypoint_2d106_ensemble",
    inputs=[raw_for_kps, bbox_input],
    outputs=[httpclient.InferRequestedOutput("LANDMARKS_106")],
)
landmarks_106_batch = kps_response.as_numpy("LANDMARKS_106")
if landmarks_106_batch.shape != (1, 106, 2):
    raise RuntimeError("response batch size must be 1 with shape [1,106,2]")
landmarks_106 = landmarks_106_batch[0]

landmarks_5 = np.empty((5, 2), dtype=np.float32)
landmarks_5[0] = landmarks_106[33:43].mean(axis=0)
landmarks_5[1] = landmarks_106[87:97].mean(axis=0)
landmarks_5[2] = landmarks_106[86]
landmarks_5[3] = landmarks_106[52]
landmarks_5[4] = landmarks_106[61]

landmarks_5_batch = np.ascontiguousarray(landmarks_5[None, ...])
raw_for_rec = httpclient.InferInput("RAW_IMAGE", list(image_batch.shape), "UINT8")
raw_for_rec.set_data_from_numpy(image_batch)
landmark_input = httpclient.InferInput("LANDMARK", list(landmarks_5_batch.shape), "FP32")
landmark_input.set_data_from_numpy(landmarks_5_batch)
rec_response = client.infer(
    model_name="face_recognition_pipeline",
    inputs=[raw_for_rec, landmark_input],
    outputs=[httpclient.InferRequestedOutput("EMBEDDING")],
)
embedding_batch = rec_response.as_numpy("EMBEDDING").astype(np.float32, copy=False)
if embedding_batch.shape != (1, 512):
    raise RuntimeError("response batch size must be 1 with shape [1,512]")
embedding = embedding_batch[0]
norm = float(np.linalg.norm(embedding.astype(np.float64)))
if not np.isfinite(norm) or norm <= 0.0:
    raise RuntimeError(f"invalid embedding norm: {norm}")
normalized = embedding / norm
print("embedding shape:", embedding.shape)
print("raw norm:", norm)
print("normalized norm:", float(np.linalg.norm(normalized)))
```

### 6.5 `adaface_recognition_pipeline`

链路：OpenCV BGR 原图和五点 → `adaface_preprocess` 相似变换对齐到 `112×112`、保持 BGR、执行 `(x-127.5)/127.5` 并转 FP32 CHW → `adaface_ir50_webface4m_onnx` → L2 归一化 512 维 embedding。五点顺序沿用上一节，调用方不要预先换成 RGB，并必须分别发送 `RAW_IMAGE [1,H,W,3]` 与 `LANDMARK [1,5,2]`。

| Tensor | 请求/响应 shape | 含义 |
| --- | --- | --- |
| `RAW_IMAGE` | UINT8 `[1,H,W,3]` | OpenCV BGR HWC 原图，显式 B=1 |
| `LANDMARK` | FP32 `[1,5,2]` | 左眼、右眼、鼻尖、左嘴角、右嘴角的原图坐标 |
| `EMBEDDING` | FP32 `[1,512]` | AdaFace R50 / WebFace4M 的 L2 归一化特征 |

HTTP 客户端说明与请求构造集中在 `test/test_adaface_image.py`。`--landmarks` 指向严格 JSON 文件，其内容必须是左眼、右眼、鼻尖、左嘴角、右嘴角五个有限数值 `[x,y]` 点，并与解码原图处于同一坐标系：

#### 完整调用示例：`adaface_recognition_pipeline`

```powershell
python test\test_adaface_image.py `
  --image D:\data\face.jpg `
  --landmarks D:\data\face-5pt.json `
  --url localhost:8000
```

客户端通过 OpenCV 读取并保持 BGR，严格核对响应为有限 FP32 `[1,512]`、首维为 1，随后选择第 0 行并检查 L2 norm。该入口直接传输完整 `RAW_IMAGE` 像素数组，请求体随 `H×W×3` 增长。联调前必须核对 Triton HTTP、反向代理和 API 网关的 body size 与超时限制；生产环境应设置受控的图片单边/总像素上限，并与服务端校验保持一致，避免过大请求在到达模型前被拒绝或长时间占用连接。

AdaFace 和现有 `face_recognition_pipeline` / `w600k_r50_trt` 即使都返回 512 维，也不是同一向量空间。必须使用独立 collection/index 或重建全部 gallery，并分别标定相似度阈值；禁止把两者向量混写、交叉查询或沿用同一阈值。

### 6.13 `yolo26s_seg_ensemble`

链路：BGR 原图 → 七档固定矩形 letterbox（见 5.4 节）→ RGB NCHW → 分割 TensorRT plan → 原图坐标检测框和固定大小 mask crop。固定 640×640 探针输出 `output0 [1,300,38]` 和 `output1 [1,32,160,160]`，与保留的 ONNX 参考签名一致；38 等于 6 个检测字段加 32 个 mask 系数。

后处理仅保留 COCO `person`（`class_id=0`）且 `score >= 0.5` 的有效检测框，再按置信度稳定降序保留最多 100 个人物并生成 mask crop。非人物类别在排序、限量和 mask 生成前过滤，不占用返回名额；模型本身仍执行原有多类别推理。以下有效检测和 mask 均仅对应人物。

- `DETECTIONS [B,M,6]` FP32：每行是原图坐标 `[x1,y1,x2,y2,score,class_id]`。
- `MASK_CROPS_PACKED [B,M,160,20]` UINT8：对 160×160 二值 crop 的每行使用 `np.packbits(..., axis=-1, bitorder="big")`，每字节从最高位到最低位表示相邻 8 个像素，与 `DETECTIONS` 的前两维和槽位一一对应；每个 crop 覆盖对应检测框，不是原图大小 mask。
- `NUM_DETECTIONS [B,1]` INT32：每个样本的有效前缀长度。
- `M = max(1, max(NUM_DETECTIONS))`，且 `1≤M≤100`。没有检测结果时仍返回一个全零占位槽；每个样本在自身 `NUM_DETECTIONS` 之后的检测和 crop 都为零填充。

API v3 每个槽位传输 3,200 字节，为原来 25,600 字节的 1/8；模型采样、0 阈值、检测框、计数及逻辑像素预算均不改变。服务端只保留一个 160×160 二值临时 crop，逐项打包到输出，避免分配完整未压缩 batch。调用方先对有效前缀执行 `np.unpackbits(..., axis=-1, count=160, bitorder="big")` 恢复 0/1。

只有业务确实需要整图 mask 时，调用方才应将对应 160×160 crop 以最近邻插值缩放到检测框的像素宽高，再写入全零 `[H,W]` 数组的框内区域。这样线上响应大小只随 `B×M` 增长，不再随原图分辨率成倍增长。

#### 完整调用示例：`yolo26s_seg_ensemble`

```python
import os
from pathlib import Path

import cv2
import numpy as np
import tritonclient.http as httpclient

url = os.environ.get("TRITON_HTTP_URL", "127.0.0.1:8000")
image_path = Path(os.environ["TRITON_SAMPLE_IMAGE"])
image = cv2.imread(str(image_path), cv2.IMREAD_COLOR)
if image is None:
    raise RuntimeError(f"cannot read image: {image_path}")

client = httpclient.InferenceServerClient(url=url, verbose=False)
image_batch = np.ascontiguousarray(image[None, ...], dtype=np.uint8)
raw_image = httpclient.InferInput("RAW_IMAGE", list(image_batch.shape), "UINT8")
raw_image.set_data_from_numpy(image_batch)
response = client.infer(
    model_name="yolo26s_seg_ensemble",
    inputs=[raw_image],
    outputs=[
        httpclient.InferRequestedOutput("DETECTIONS"),
        httpclient.InferRequestedOutput("MASK_CROPS_PACKED"),
        httpclient.InferRequestedOutput("NUM_DETECTIONS"),
    ],
)
detections_batch = response.as_numpy("DETECTIONS")
mask_crops_batch = response.as_numpy("MASK_CROPS_PACKED")
counts = response.as_numpy("NUM_DETECTIONS")
if counts.shape != (1, 1):
    raise RuntimeError("NUM_DETECTIONS must have shape [1,1]")
if (
    detections_batch.ndim != 3
    or detections_batch.shape[0] != 1
    or detections_batch.shape[2] != 6
):
    raise RuntimeError("DETECTIONS must have shape [1,M,6]")
m = detections_batch.shape[1]
if not 1 <= m <= 100:
    raise RuntimeError("DETECTIONS capacity M must be in [1,100]")
if mask_crops_batch.shape != (1, m, 160, 20):
    raise RuntimeError("MASK_CROPS_PACKED must have shape [1,M,160,20]")
count = int(counts[0, 0])
if count < 0 or count > 100 or m != max(1, count):
    raise RuntimeError("response does not use canonical dynamic capacity")
if mask_crops_batch.dtype != np.uint8:
    raise RuntimeError("MASK_CROPS_PACKED must have dtype uint8")
if np.any(detections_batch[0, count:]) or np.any(mask_crops_batch[0, count:]):
    raise RuntimeError("padding after NUM_DETECTIONS must be zero")
detections = detections_batch[0, :count]
mask_crops = np.unpackbits(
    mask_crops_batch[0, :count], axis=-1, count=160, bitorder="big"
)

# 按需恢复第一项整图 mask；不需要整图 mask 时跳过这一步。
full_mask = None
if count:
    x1, y1, x2, y2 = (
        int(round(float(value))) for value in detections[0, :4]
    )
    x1 = int(np.clip(x1, 0, image.shape[1]))
    x2 = int(np.clip(x2, 0, image.shape[1]))
    y1 = int(np.clip(y1, 0, image.shape[0]))
    y2 = int(np.clip(y2, 0, image.shape[0]))
    if x2 <= x1 or y2 <= y1:
        raise RuntimeError("detection bbox has no pixel area after clipping")
    full_mask = np.zeros(image.shape[:2], dtype=np.uint8)
    full_mask[y1:y2, x1:x2] = cv2.resize(
        mask_crops[0],
        (x2 - x1, y2 - y1),
        interpolation=cv2.INTER_NEAREST,
    )

print("count:", count)
print("detections [x1,y1,x2,y2,score,class_id]:\n", detections)
print("returned mask crop shape:", mask_crops_batch.shape)
print("valid mask crop shape:", mask_crops.shape)
print("first restored full mask shape:", None if full_mask is None else full_mask.shape)
```

### 6.14 `sixdrepnet_ensemble`

`sixdrepnet_ensemble` 接收 OpenCV BGR 顺序的 dense `UINT8 RAW_FACE_IMAGE [B,H,W,3]`；同一次请求内所有样本必须具有相同 `H`、`W`，不同尺寸需分请求或按 shape 分桶。预处理逐样本转为 RGB，短边等比缩放到 224、中心裁剪 `224×224`，再使用 ImageNet `mean=[0.485,0.456,0.406]` 和 `std=[0.229,0.224,0.225]` 归一化。输出 `HEAD_POSE [B,3]` 为 FP32 角度，列顺序固定为 `[pitch,yaw,roll]`，单位为度。

当前运行时接受 `1 <= B <= 4`；以下是 batch-4 示例：

```python
import os
from pathlib import Path

import cv2
import numpy as np
import tritonclient.http as httpclient

url = os.environ.get("TRITON_HTTP_URL", "127.0.0.1:8000")
paths = [Path(os.environ[f"TRITON_FACE_IMAGE_{index}"]) for index in range(4)]
images = [cv2.imread(str(path), cv2.IMREAD_COLOR) for path in paths]
if any(image is None for image in images):
    raise RuntimeError("one or more face images could not be read")
if len({image.shape for image in images}) != 1:
    raise RuntimeError("all images in one dense request must have the same H and W")

image_batch = np.ascontiguousarray(np.stack(images), dtype=np.uint8)
raw_face_image = httpclient.InferInput(
    "RAW_FACE_IMAGE", list(image_batch.shape), "UINT8"
)
raw_face_image.set_data_from_numpy(image_batch)
client = httpclient.InferenceServerClient(url=url, verbose=False)
response = client.infer(
    model_name="sixdrepnet_ensemble",
    inputs=[raw_face_image],
    outputs=[httpclient.InferRequestedOutput("HEAD_POSE")],
)
head_pose = response.as_numpy("HEAD_POSE")
if head_pose.shape != (4, 3) or not np.isfinite(head_pose).all():
    raise RuntimeError(f"invalid HEAD_POSE result: {head_pose.shape}")
print("[pitch, yaw, roll] degrees:\n", head_pose)
```

## 8. 公开 ensemble 内部调度

1. `clip_ensemble_trt`：`IMAGE_BYTES` → `clip_image_preprocess` → `clip_image_trt` → `unnorm_image_features`。
2. `clip_text_ensemble`：`TEXT` → `clip_text_preprocess` → `clip_text_trt` → `unnorm_text_features`。
3. `face_keypoint_2d106_ensemble`：`RAW_IMAGE + BBOX` → `face_keypoint_2d106_pre` → `face_keypoint_2d106` → `face_keypoint_2d106_post` → `LANDMARKS_106`。
4. `face_qa_ensemble`：`RAW_FACE_IMAGE + LANDMARK` → `face_qa_pre` → `face_qa` → `face_qa_postprocess` → `quality_score`。
5. `face_recognition_pipeline`：`RAW_IMAGE + LANDMARK` → `face_rec_pre` → `w600k_r50_trt` → `EMBEDDING`。
6. `osnet_ain_x1_0_image_ensemble`：`IMAGE_BYTES` → `osnet_ain_x1_0_image_preprocess` → `osnet_ain_x1_0_onnx` → `embedding`。
7. `sbs_r50_ibn_image_ensemble`：`IMAGE_BYTES` → `sbs_r50_ibn_image_preprocess` → `sbs_r50_ibn_onnx` → `embedding`。
8. `TBPS_clip_image_ensemble`：`IMAGE_BYTES` → `TBPS_clip_image_preprocess` → `TBPS_clip_image_trt` → `image_feat`。
9. `TBPS_clip_text_ensemble`：`TEXT_IN` → `TBPS_clip_text_preprocess` → `TBPS_clip_text_trt` → `text_feat`。
10. `yolo26m_pose_ensemble`：`RAW_IMAGE` → `yolo26m_pose_preprocess` → `yolo26m_pose_onnx` → `yolo26m_pose_postprocess` → `DETECTIONS + KEYPOINTS + NUM_DETECTIONS`。
11. `yolo26s_seg_ensemble`：`RAW_IMAGE` → `yolo26s_seg_preprocess` → `yolo26s_seg_onnx` → `yolo26s_seg_postprocess` → `DETECTIONS + MASK_CROPS_PACKED + NUM_DETECTIONS`。
12. `yolov8n_face_ensemble`：`RAW_IMAGE` → `yolov8n_face_preprocess` → `yolov8n_face_onnx` → `yolov8n_face_postprocess` → `DETECTIONS + NUM_DETECTIONS`。
13. `adaface_recognition_pipeline`：`RAW_IMAGE + LANDMARK` → `adaface_preprocess` → `adaface_ir50_webface4m_onnx` → `EMBEDDING`。
14. `sixdrepnet_ensemble`：`RAW_FACE_IMAGE` → `sixdrepnet_preprocess` → `sixdrepnet_onnx` → `sixdrepnet_postprocess` → `HEAD_POSE`。

完整节点清单以 `model_repository/*/config.pbtxt` 为准。新增、删除或重命名内部节点时，必须同步更新对应 ensemble 映射和本文的公开入口调度说明。

## 9. 模型更新与历史数据迁移

### 9.1 哪些更新必须重建历史数据

| 数据类型 | 产生模型 | 更新后的处理原则 |
| --- | --- | --- |
| w600k 人脸 512 维向量 | `face_recognition_pipeline` / `w600k_r50_trt` | 模型、5 点映射、对齐模板、颜色、归一化任一变化都视为新特征空间。全量重算向量并新建索引或新分区；旧向量不得与新查询向量混用。 |
| AdaFace 人脸 512 维向量 | `adaface_recognition_pipeline` / `adaface_ir50_webface4m_onnx` | 与 w600k 即使同为 512 维也不兼容。必须独立建库或重建全部 gallery，并单独标定阈值；禁止与 w600k 混写、交叉查询或复用阈值。 |
| 行人 2048 维向量 | `sbs_r50_ibn_image_ensemble` | checkpoint、预处理或导出包装变化后全量重算。即使新旧都为 2048 维也不能混用；MSMT17 与 DukeMTMC 等训练域必须分开。 |
| 行人 512 维向量 | `osnet_ain_x1_0_image_ensemble` | 与 SBS 是不同模型族，维度也不同，必须独立 collection/index；更新 checkpoint 或预处理后全量重算。 |
| Chinese-CLIP 512 维图文向量 | `clip_ensemble_trt`、`clip_text_ensemble` | 图像和文本编码器必须来自同一发布版本。任一侧模型、tokenizer、长度、颜色或归一化变化时，两侧历史向量一起重算。 |
| TBPS 512 维图文向量 | `TBPS_clip_image_ensemble`、`TBPS_clip_text_ensemble` | 图像与文本侧必须成对版本化。不能与 Chinese-CLIP 向量混用，也不能把当前基础 CLIP 向量与未来 TBPS 微调模型向量混用。 |
| 人脸质量分 | `face_qa_ensemble` | 模型、五点映射、对齐或连续均值规则改变时重算历史分数；v1 整数计数分与 v2 连续分必须保存不同算法版本，避免同一业务阈值混用。 |
| 检测框、106 点、人体姿态、分割 mask | 对应 YOLO/关键点 ensemble | 如果这些结果持久化并参与对齐、筛选或业务统计，模型、阈值、letterbox、颜色或坐标恢复变化后应从原始图片重算。只保存下游向量而不保存原图时，将无法完整回溯。 |

向量库至少保存以下伴随字段：`model_family`、`model_release`、ONNX 活动文件或构建参考源 SHA256、预处理版本、颜色契约、输出是否 L2 归一化、维度、源图片或对象 ID、生成时间。检测、关键点、质量分和分割结果还应保存阈值、坐标恢复规则与后处理版本；全部原生节点的结果同时关联源 ONNX 与所用 plan 的身份、精度、optimization profile 和构建环境记录。为保持原有制品可追溯性，旁车中历史 `profile: throughput` 字段继续保留，但不用于选择运行配置。检索时先按同一特征空间过滤，再做相似度计算。仅切换后端也必须通过数值及检索门禁，不能因公开 schema 未变就假定旧索引兼容。

live 成功只说明进程存活；全局 ready 成功表示 strict readiness 下启动时选择的加载目标就绪（`all` 为全仓库，subset 为所选闭包）；repository index 用于逐模型核对状态；单模型 ready 只证明指定模型已就绪；metadata 与 config 用于核对运行时签名、backend 和 batch 配置。任何请求失败或返回内容不符合本手册时都不得发布。

### 10.2 读取 ONNX 签名与模型制品身份

在仓库根目录使用项目的 ONNX Python 环境读取全部 14 份 ONNX（3 个 ONNX Runtime 活动模型及 11 个原生节点构建/参考源）；此脚本不读取或验证 plan：

```python
from __future__ import annotations

import hashlib
from pathlib import Path

import onnx


root = Path("model_repository")
for path in sorted(root.glob("*/1/model.onnx")):
    graph = onnx.load(str(path), load_external_data=False)
    initializers = {value.name for value in graph.graph.initializer}

    def describe(value: onnx.ValueInfoProto) -> tuple[str, list[object]]:
        tensor = value.type.tensor_type
        dims: list[object] = []
        for dim in tensor.shape.dim:
            if dim.HasField("dim_value"):
                dims.append(dim.dim_value)
            elif dim.HasField("dim_param"):
                dims.append(dim.dim_param)
            else:
                dims.append("unknown")
        return onnx.TensorProto.DataType.Name(tensor.elem_type), dims

    inputs = [
        (value.name, *describe(value))
        for value in graph.graph.input
        if value.name not in initializers
    ]
    outputs = [(value.name, *describe(value)) for value in graph.graph.output]
    digest = hashlib.sha256(path.read_bytes()).hexdigest()
    opsets = [(item.domain or "ai.onnx", item.version) for item in graph.opset_import]
    print(path.parent.parent.name, graph.ir_version, opsets, inputs, outputs, digest)
```

ONNX Runtime 活动文件和全部原生节点参考源必须存在且可读取；单独核对哈希可使用 PowerShell，预期身份值见 [模型来源与制品身份](模型来源与制品身份.md)：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'model_repository\adaface_ir50_webface4m_onnx\1\model.onnx'
```

### 10.4 排障顺序

出现颜色、坐标、batch 或输出异常时，按边界逐层定位：

1. 核对线上调用的公开模型名和 `config.pbtxt` 输入输出名，不先根据目录名猜模型身份。
2. 保存入口原始数组，确认 OpenCV 路径是 BGR HWC UINT8，编码图片路径是完整文件字节而不是像素数组。
3. 单独运行 Python 预处理节点，检查颜色、shape、dtype、数值范围和是否连续；106 点链路应只有 `blobFromImage` 的 `swapRB=True` 这一处换色，AdaFace 链路则必须全程保持 BGR。
4. 直接运行所选 ONNX Runtime 或 TensorRT 节点并与本节模型签名比较；YOLO 可用 `[1,3,640,640]` 固定探针检查输出，再覆盖七档尺寸及 batch 范围。制品字节身份由哈希和构建 provenance 核对。
5. 单独运行后处理，检查 letterbox 比例/偏移、原图宽高、框顺序、106→5 映射和空结果分支。
6. 最后检查客户端是否再次换色、归一化、交换左右点位或把未归一化特征当作 cosine 向量。
