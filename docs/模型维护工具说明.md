# 模型维护工具说明

[返回文档导航](../README.md#文档导航)

日常使用 `python -m tools.model_pipeline` 完成 **下载源文件 → 导出 ONNX → 构建 plan**。完整命令见[模型下载与转换](模型下载与转换.md)，源文件身份和固定下载地址由 [catalog.json](../tools/model_pipeline/catalog.json) 管理。本文说明工具职责、可选本地源文件和输出目录。

## 转换流程与工具职责

```text
源权重 / 官方源 ONNX
        ↓ acquire：下载或本地复制，校验大小与 SHA256
artifacts/sources/<source_id>/<sha256>/<filename>
        ↓ onnx --no-reference：固定导出配方，CPU 校验
artifacts/<candidate>/<model>/1/model.onnx + model.rebuild.json
        ↓ plan：目标设备 TensorRT，显式 batch/精度/workspace
artifacts/<candidate-plan>/<model>/1/model_bN.plan + 构建记录
```

| 入口或目录（相对 `tools/`） | 职责 |
| --- | --- |
| `model_pipeline list / audit` | 模型别名、源文件和当前 ONNX 身份检查 |
| `model_pipeline acquire` | 按固定地址获取文件并核对 SHA256，提取 InsightFace 包内指定模型 |
| `model_pipeline onnx --no-reference` | 仅凭源文件导出；原本已是 ONNX 的源模型做动态 batch 包装 |
| `model_pipeline plan` | 构建独立 TensorRT 候选，支持 B1/B4/B8 等 |
| `export_*.py / dynamic_batch_onnx.py` | 统一入口使用的模型结构、导出和动态 batch 校验实现 |
| `build_tensorrt_plans.py` | 通用 TensorRT 构建实现；直接部署 CLI 只构建 B1～4 `model_throughput.plan` |
| `build_yolo_tensorrt_plans.py` | YOLO 部署兼容入口；同样只构建 B1～4 `model_throughput.plan` |
| `models/` | 可选本地源文件位置，统一入口只读；各模型子目录用 `.gitkeep` 保留 |

`--no-reference` 不要求现存 ONNX；省略它则额外对照当前 ONNX 的数值，也可以用 `--reference-root` 指定参考目录。工具记录是否做过参考对照，两种模式的导出配方相同。

`model_pipeline plan` 的 `--max-batch` 必填，可显式构建 B1/B4/B8 等独立候选。活动部署只使用 B1～4 `model_throughput.plan`；底层部署构建器没有运行配置参数，模型配置也不再需要生成步骤。

## 可选本地模型源文件

[tools/models/](../tools/models) 用于存放已有的源权重或官方源 ONNX。子目录中的 `.gitkeep` 只用于让 Git 保留目录结构；实际模型二进制由仓库 `.gitignore` 忽略。

`acquire` 优先校验缓存，其次读取 [catalog.json](../tools/model_pipeline/catalog.json) 中 `local_path` 指向的本地文件，最后按固定地址下载。本地文件通过大小和 SHA256 校验后会复制到缓存，工具不会修改这里的源文件。

从仓库根目录运行时，默认下载缓存是：

```text
artifacts/sources/<source_id>/<sha256>/<filename>
```

可以用 `--cache <目录>` 指定其他缓存位置；相对路径以命令执行目录为准。InsightFace 原始压缩包另存于 `<cache>/archives/<sha256>/<filename>`。下载不会自动回填 `tools/models`，缓存目录也不能设置为 `tools/models`。

本地源文件可以放在其他位置，通过 `--source-file SOURCE_ID=PATH` 指定。文件名、源身份和具体子目录以 catalog 为准。

## 候选输出与部署目录

ONNX 和 plan 候选由 `--output` 指定位置，与源文件目录和活动部署目录分开。完整命令见[模型下载与转换](模型下载与转换.md)。

统一入口拒绝输出到当前 `model_repository`、`tools/models`、`.env`、Compose 和 `.git` 范围，已存在的模型候选拒绝覆盖。模型专用实现及现有制品身份、发布校验和部署 plan 构建能力由统一入口复用；旧的独立动态 batch 包装、YOLO 导出和 CLIP 默认路径入口已移除。
